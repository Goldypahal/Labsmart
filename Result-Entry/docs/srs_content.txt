1. Introduction
1.1 Purpose
This Software Requirements Specification (SRS) document describes the functional and non-functional requirements for PathLab LIMS — a Pathology Laboratory Information Management System. The system is designed to streamline the complete workflow of a diagnostic pathology laboratory: from patient registration and test ordering, through sample processing and result entry, to report generation and delivery via WhatsApp, Email, or Print.
This document is intended for developers, testers, project managers, and laboratory administrators involved in the design, development, and validation of the system.
1.2 Scope
PathLab LIMS covers the following functional areas:
Patient Registration and Demographics Management
Test Selection from a structured test catalog
Result Entry with reference range validation
Auto-fetched date and time with override capability
Referred Doctor Management with intelligent search and suggestions
Report Generation and Delivery via WhatsApp, Gmail, and Print
Bill / Invoice Generation
User Role Management and Access Control
Audit Logs and Data Security

2. Overall Description
2.1 Product Perspective
PathLab LIMS is a standalone, desktop-first application with optional cloud synchronization capabilities. It replaces manual paper-based workflows in small to mid-size diagnostic laboratories. The system integrates with common communication platforms (WhatsApp Business API, Gmail SMTP) and standard printers. It is inspired by existing solutions such as LabSmart and is designed for Indian diagnostic lab environments, supporting common Indian test panels, referral doctor ecosystems, and local compliance needs.
2.2 Product Functions (High-Level Summary)
The system shall perform the following major functions:
Patient Registration — Capture patient demographic, contact, and clinical information.
Sample & Test Management — Select tests from a master catalog, assign sample IDs.
Result Entry — Enter test values with auto-validation against reference ranges.
Date/Time Management — Auto-fetch system date/time; allow manual override.
Doctor Management — Maintain referred doctor registry with smart search and autocomplete.
Report Generation — Generate formatted PDF reports.
Report Delivery — Send reports via WhatsApp, Gmail, or direct print.
Billing & Invoicing — Calculate charges, apply discounts, generate receipts.
User & Role Management — Admin, Lab Technician, Receptionist roles.
Audit & Compliance — Maintain logs of all critical activities.

2.4 Operating Environment
Platform: Windows 10/11 (Primary), Web-based interface (secondary)
Database: SQLite (offline/standalone) or PostgreSQL (networked/cloud)
Minimum RAM: 4 GB; Recommended: 8 GB
Minimum Storage: 20 GB free disk space
Network: Internet required for WhatsApp/Gmail delivery; offline mode for core functions
Printer: Any standard A4 thermal or laser printer with Windows drivers
Browser (web version): Chrome 110+, Edge 110+, Firefox 110+
2.5 Design and Implementation Constraints
Reports must be exportable as PDF (ISO 32000 compliant).
Patient data must be stored encrypted at rest (AES-256).
WhatsApp integration shall use the WhatsApp Business API or Twilio gateway.
Gmail integration shall use OAuth 2.0 for authentication.
The system shall comply with data privacy norms under IT Act 2000 and DPDP Act 2023 (India).
The system should support multi-user concurrent access in LAN mode.
2.6 Assumptions and Dependencies
The laboratory has a stable internet connection for WhatsApp/Gmail delivery features.
A WhatsApp Business API account (or approved gateway like Twilio/AiSensy) is provisioned.
Gmail SMTP credentials or OAuth 2.0 app credentials are configured by the administrator.
Test reference ranges are pre-configured by the administrator before go-live.
Referred doctors are onboarded with at least their name and specialization.

4.2 Security
NFR-SC-001: All data at rest shall be encrypted using AES-256.
NFR-SC-002: All data in transit (API calls, email) shall use TLS 1.2 or higher.
NFR-SC-003: OAuth 2.0 shall be used for Gmail integration; API keys shall be stored in an encrypted config store.
NFR-SC-004: Patient reports sent via WhatsApp shall not be stored in third-party servers beyond transient delivery use.
NFR-SC-005: System shall comply with IT Act 2000 and DPDP Act 2023 for personal data handling.
4.3 Usability
NFR-US-001: The UI shall be designed for keyboard-first data entry; all primary actions achievable without mouse.
NFR-US-002: Result entry workflow shall be completable in under 3 minutes for a standard CBC panel.
NFR-US-003: All error messages shall be descriptive and actionable.
NFR-US-004: The application shall support Hindi language interface (optional localization toggle).
NFR-US-005: System shall provide contextual inline help/tooltips for complex fields.
4.4 Reliability and Availability
NFR-RA-001: System shall achieve 99.5% uptime in LAN deployment.
NFR-RA-002: Automatic daily database backup shall be performed and stored locally and optionally on cloud.
NFR-RA-003: System shall gracefully handle network failure — core workflows (registration, result entry) shall function offline.
NFR-RA-004: Database shall support transaction rollback in case of crash during write operations.
4.5 Maintainability
NFR-MT-001: Codebase shall follow documented coding standards.
NFR-MT-002: Test master catalog, reference ranges, and pricing shall be configurable by the admin without code changes.
NFR-MT-003: Report templates shall be editable via a template editor without developer intervention.
4.6 Scalability
NFR-SL-001: Database design shall support migration from SQLite to PostgreSQL without data loss.
NFR-SL-002: Application architecture shall support a future web-based multi-branch portal.
5. External Interface Requirements
5.1 User Interface
The system shall provide a desktop GUI (Electron/web-based) with the following screens:
Dashboard — Daily summary: registrations, pending reports, payments due.
Patient Registration — Multi-step form with test selection inline.
Result Entry Workbench — Tabular data entry per test.
Report Preview & Delivery — Preview panel with WhatsApp/Email/Print action buttons.
Doctor Registry — CRUD screen with search and autocomplete preview.
Test Catalog Manager — Manage tests, packages, reference ranges.
Billing Screen — Invoice creation, payment recording.
Admin Panel — User management, system settings, audit logs.

6. System Constraints
WhatsApp report delivery requires an active approved WhatsApp Business API account; unofficial WhatsApp automation is not supported.
The system does not support direct integration with analytical instruments in Phase 1 (manual result entry only).
Bulk result import from analyzer (LIS/ASTM) is planned for Phase 2.
The system is designed for single-branch use in Phase 1; multi-branch support is a Phase 2 feature.
